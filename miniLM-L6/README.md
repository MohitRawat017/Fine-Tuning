# 🧭 MiniLM-L6 — Intent Router

Fine-tunes **`sentence-transformers/all-MiniLM-L6-v2`** (22M params) into a
5-way intent classifier that tells the voice assistant *what kind of request* a
query is — the "understand it" stage of the pipeline.

| | |
|---|---|
| Base model | `sentence-transformers/all-MiniLM-L6-v2` |
| Task | Text → intent (casual / productivity / system / research / communication) |
| Technique | Full fine-tune + mean pooling + classification head |
| Dataset | 400 hand-crafted queries (80 per intent) |
| VRAM | ~2 GB (tiny model) |

---

## The Dataset

`dataset.jsonl` holds 400 voice-style queries — 80 per intent — generated by
`generate_dataset.py`. The generator is hand-crafted rather than scraped, so it
matches how people *actually* talk to assistants:

```jsonl
{"text": "hey um set an alarm for 6:30 in the morning", "label": "productivity", "label_id": 1}
{"text": "do the needful and send mail", "label": "communication", "label_id": 4}
```

It deliberately includes **hesitations** ("hey um..."), **typos** ("set alram"),
and **Indian-English phrasings** ("kindly...", "do the needful") — exactly the
kind of noise a real ASR pipeline produces.

```bash
python generate_dataset.py   # reproduces dataset.json + dataset.jsonl (seeded)
```

## Training

```bash
python train_minilm.py
```

Details worth knowing:

- **Mean pooling** — the same pooling the SentenceTransformers library applies at
  inference time, so train-time and serve-time embeddings are consistent.
- **Label smoothing (0.05)** — reduces overconfidence on the small dataset.
- **Early stopping** (patience 3) + **stratified split** (balanced intents).
- Saves the **best checkpoint by validation accuracy** to `tsuzi_intent_model.pt`
  (git-ignored) and the tokenizer to `tsuzi_tokenizer/`.

Expect **>95% validation accuracy** after 5 epochs — the intents are quite
distinct.

## Inference

```bash
python inference.py                     # demo + interactive mode
python inference.py "open vscode please"  # single query
```

Each prediction returns the intent, a confidence score, the full probability
distribution, and the list of assistant actions that make sense for that intent
(e.g. `productivity → [set_timer, set_alarm, ...]`) — which is exactly the
signal the FunctionGemma router consumes next in the pipeline.

The inference script uses the locally-saved `tsuzi_tokenizer/` when present
(offline-capable), falling back to the HF hub copy otherwise.
